# POLKA FRONTIER — 立体マップ / 衝突・経路探索 Proof of Concept

> **開発前の技術検証です。MMORPG本体・正式キャラクター・認証・戦闘・発掘・オンライン同期は未実装です。** 2D表示に置換する可能性を維持した、独立した3D座標系のデモです。

## 起動

必要: **Node.js 20以上**。追加の npm install や Python は不要です。

```bash
npm test
npm run serve
```

PCブラウザで `http://localhost:8000` を開きます。npm install は不要。**ダブルクリックして file:// で開かず、HTTPサーバーから開いてください。**

## 操作

- 地面クリック: 選択中の歩行面への最短経路探索・自動移動
- 「地上を指定」「橋上を指定」: 同一X/Zに2つ存在する歩行面を選ぶ
- WASD / 方向キー: 手動移動 / Q・E: カメラ回転 / マウスホイール: ズーム / Esc: 停止
- 橋の上へ / 橋の下を通る / 穴を避ける / 戻る: シナリオ実行
- 木箱を撤去・復元: 動的障害物の衝突データと経路グラフを再生成
- 移動速度+40%: 課金アクセサリーで想定される高速移動の操作感を確認

## このPoCで検証すること

1. 地上 (y=0) と橋の上 (y=3m) が平面で重なっても、歩行面・経路を区別できる。
2. 上り・下りの接続は橋の両端の坂（階段の当たり判定の簡略モデル）でのみ行う。橋の中央から上下へワープしない。
3. 穴、木の幹、壁、木箱の周囲にプレイヤー半径0.27mの余白を含めて進入を禁止する。
4. 木箱撤去・再設置で、歩行可能領域・経路が再生成される。
5. 3Dメッシュの奥行き（深度テスト）で、木・橋の前後にキャラが隠れる。
6. 決定的乱数シードの1000経路テストを実行する。短時間のPoC用であり、衝突判定の完全性を保証するものではない。

## 技術上の注意点

- **単一の歩行トポロジーモデルが正本**。`src/world.js` は歩行面・障害物・経路を定義し、`src/renderer.js` は視覚表示のみ。将来の本番用GLB/NavMeshの代替ではありません。
- 表示は自前の小さなWebGL1レンダラー。PoCに外部ランタイムや未確認アセットを持ち込まず構造検証するための選択で、**本番採用する3Dエンジンではありません**。
- サーバー権威の移動検証・リアルタイム同期・自動NavMeshベイク・接触剛体・高さ方向の物理射線判定・モバイル最適化は未実装です。
- `window.polkaDebug` は開発用の検査APIです。本番では公開しないか権限分離してください。
- 3D地形を絵画調に仕上げる前に、この概念をBabylon.js + Recast、または適切な物理/Navigationスタックへ移植・再検証する工程が必要です。
- `docs/SPEC_INTEGRATION.md` は旧10能力仕様と新12能力仕様を区別します。11月の改訂資料が一部提案であることを保ったまま保存しています。
