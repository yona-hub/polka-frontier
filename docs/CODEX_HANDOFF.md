## 次のCodexタスク（順番厳守）
### P0 ブラウザの実機QAとバグ修正
- `npm test` → `npm run serve`。自分のブラウザでシナリオ4種類を実操作し、スクリーンショット/コンソールログを保存。
- 移動速度+40%の衝突、手動移動の障害物すり抜け、橋の上下切替、木の遮蔽を修正。
- 視覚メッシュと計算上の衝突領域を重ねるデバッグビューを作る。地上/橋上のY値を表示。
- 最低でも1000組の経路**計算**に加え、実際のキャラクター移動を1000通り自動実走行するE2Eを追加。
### P1 本番候補エンジンの立体地形PoC
- 現コードのゲーム仕様は保持して、Babylon.js + Recast等で地形メッシュから歩行面/ナビゲーションを作る別実装を試す（既存PoCを消さず別ディレクトリ/ブランチで）。
- 同一X/Zに上下2面の歩行領域、階段、穴、壁・木、除去可能障害物が正しく保てること。サーバーもsurface/floor/Yを検証可能にする。
- 単一の真のマップデータから表示/衝突/サーバー検証情報を生成し、見た目に後付けの衝突ポリゴンを手描きしない。
### P2 縦切りゲーム実装
- モンスター巡回→索敵→追跡→攻撃→帰還→再出現、ターゲット占有、通常攻撃/基本スキル。
- 発掘ポイントとドロップテーブル、サーバー決定の抽選、アイテム獲得、重量制。
- 12能力+4BP、旧能力式は採用禁止。新仕様の不足点は勝手に固定せず、仮値と明記してデータ化。
- Colyseus等による2クライアントでの共有状態とDB永続化はこの段階で組込む。
### P3 アートの準備
- `assets/reference/item_style_2026-11-20.png`（ZIPに同梱）から**独自ペインターリー調**のスタイル基準を策定。画像のコピーでなく特徴のみ活用。
- 3D→2Dキャラ/敵の比較PoC、アイコン30点の基礎品質テスト後にバッチ量産へ。
- 制作時に `.agents/skills/mmorpg-asset-factory/SKILL.md`、`mmorpg-asset-qa`、`item-designer`、`content-balancer` を作り、`docs/ASSET_STYLE.md`の基準を読み込ませる。

## 重要な終了条件
- 「動いた」「完成」をログ・テストレポートなしに宣言しない。失敗の再現手順→修正→再テストを必須にする。
- 同時接続500人は最終目標で、PoCの成功だけでは性能を証明できない。50→100→500CCUの負荷試験が必要。
- キャラクター・アイテム・スキル・発掘・クエストは不変IDで管理し、原作由来のデータや名前を流用しない。
- 3D表示と衝突ロジックは一致しているか、同位置2階層が破綻しないか、手動/自動操作双方を試験する。
- 新仕様変更を行ったら、関連MD/JSON/テストを同一コミットで更新。旧案を上書きする場合も変更履歴を残す。
