# 3DマップPoC — 実装・検証結果
更新日: 2026-11-21

## 構成

- `src/world.js`：平面のX/Z＋高さY、地上/橋上の2層サーフェス、壁・木・穴・動的木箱、格子グラフによるA*探索。位置半径0.27mで障害物を膨張させて衝突を判断。
- `src/renderer.js`：同じ定義から簡易3Dメッシュを組み、WebGL1深度テスト・平行投影で描画。外部の原作素材なし。
- `src/main.js`：クリック移動、WASD、視点回転、ズーム、経路視覚化、木箱撤去、速度+40%。
- `tests/world.test.js`：Nodeの標準test runner。ブリッジの上下、階段接続、穴/木/壁/木箱、1000ランダム経路等を検証。

## 実行結果（2026-11-21）

	npm test

- Node.js v22.16.0、全8テスト成功、failed=0。
- 1000本の固定seed経路テストはグラフ上で各隣接エッジが有効かを検証。**物理エンジン上で1000本の実走行を測定した意味ではない**。
- ローカルHTMLサーバーは応答200を確認。
- 自動ブラウザ画像テストは実行環境のポリシーにより`ERR_BLOCKED_BY_ADMINISTRATOR`となり、WebGL画面の視覚QAは**未完了**。手元のChrome/Edgeでの操作確認が必要。

## 意図的にPoCの対象外とした項目

- Babylon.js、Unity、Godot等の実物理/NavMeshベイク、3D MeshCollider、非同期ワールド更新。
- ブラウザ2画面以上のネットワーク同期とチャンネル/サーバー負荷。
- モンスターAI、射程、発掘、育成、DB永続化、認証、経済、課金。
- アーティスト制作のキャラクター・手描き背景。現在は灰色/低ポリ風の形状検証用モデル。
- プレイヤーの壁沿い滑り、連続衝突、急角度の複数操作、歩行位置精度と描画衝突の完全一致の検証。

## 本番化前の必須ゲート

**Gate 1（このPoC）**：橋の上下の混同なし、階段経路、穴/木/壁禁止、木箱の再構築、1000グラフ経路の自動検証。結果: PASS（ブラウザ視覚QAを除く）。

**Gate 2（次のCodex作業）**：実際のBabylon.js/Three.js＋Recast NavigationまたはUnity/Godotで同じ構造を再現し、見た目メッシュとCollider/NavMeshを一致させる。キャラ移動を実走行で1000回、+40%速度、橋下や斜面/縁際の衝突、木の裏での描画を計測。すべての移動をサーバー側でも検証可能な形式にする。

**Gate 3（戦闘・発掘）**：敵/発掘ポイントを立体上に配置し、地上から橋上の敵を不正にターゲットできない、橋下と橋上で発掘を混同しない、ポータルや復帰位置が有効であることをテスト。

## 手動ブラウザ確認手順

1. `npm run serve`後、Chrome/Edgeで`http://localhost:8000`にアクセス。WebGL警告が出ない。
2. 「橋の上へ」を押し、高さ表示が0→3mになる。「橋の下を通り抜ける」は3mに上がらない。
3. 「穴を避けて歩く」で穴中心へ踏み込まない。
4. WASDを使い、木/壁/穴/橋端の衝突を確認。移動速度+40%も試す。
5. 木箱を撤去/再設置し、経路と衝突が変化することを確認。
6. 同位置で「地上を指定」「橋上を指定」を切替え、正しい階層へ向かう。
7. カメラを回転し、キャラクターが木や橋の裏に隠れることを確認。

## 既知の限界

現在のPoCは1メートル間隔の経路ノードと簡易レイ・サンプリングを使うため、細かい段差の厳密な接触判定や実物理ボディの押し戻しは扱えない。橋の階段は見た目と連続斜面コライダーの近似であり、本番ではメッシュ上のコライダー・NavMeshを作り直す。
